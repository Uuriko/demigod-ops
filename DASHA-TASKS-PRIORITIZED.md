## How to read this list

Research keeps saying the same things—and also where **template advice is wrong for us**:

1. **Memecoins win on culture + trust signals, not feature count.** Differentiator is narrative and participation, not more chrome.  
2. **Generic memecoin landing checklists** sell: mascot hook, tokenomics block, roadmap, Telegram CTA, airdrop contests. That is the **default pump template**. Dasha’s wedge is the opposite: honest mint + buy path + make/share loop, **without** “safe / verified / utility roadmap” theater.  
3. **Open source is a trust product** for builders (inspectable mint tools, remix code)—not a substitute for a working live site.  
4. **OSS growth is demo-first, not checklist-first.** Stars come from README pitch in 15s + GIF/video + one coordinated post day—not from CODEOWNERS alone.  
5. **Frontend integrity is security.** High-profile memecoin sites have been **hijacked** (malicious redirects / drainers). Ship lag and mint drift are not just ops debt.  
6. **Static hosting** is fast insurance; Webflow is fine as primary if publish unblocks.  
7. **Process should match scale.** No eliza-scale monorepo/plugin theater before strangers use Studio.

So the old 80+ list is still a **backlog inventory**. Below is a **decision order**: what to do, what to park, what to delete from the mental load.

## Research brainstorm — what the web pushed us to rethink

### 1. Template CRO vs Dasha CRO

Industry memecoin landing advice (templates / “CRO” blogs) almost always wants:

- Big character / lore hook  
- Tokenomics + roadmap sections  
- Telegram / Discord as primary community  
- Contests, airdrops, countdown hype  

**Keep from that list:** one clear hook, one clear CTA, simple narrative.  
**Reject as product goals:** fake roadmap utility, official Telegram, points/airdrop theater, “safest ways to explore” framing.

**Implication for our list:** don’t schedule “tokenomics page,” “roadmap v2,” or “join TG.” Double down on:

- Mint visible + copyable everywhere buy appears  
- Jupiter path locked to the exact CA  
- Studio = the culture CTA that templates never have  

### 2. Buy path truth (Jupiter + CA culture)

Universal Solana advice: **always verify contract address; never trust ticker alone.** Every buy CTA uses a direct Jupiter URL with SOL as input and the exact output mint. Keep the landing page free of embedded wallet code until usage proves it is needed.

**Implication:**

- Desk + home “verify mint” is a **conversion + safety** feature, not pedantry.  
- How-to-buy as a **fourth route** is usually template bloat if home already has three honest steps. Prefer **fold** unless support repeatedly fails on live desk.  
- Optional thin link to Dexscreener / explorer for “third-party check” is higher trust than a long guide.

### 3. Frontend compromise is real

Memecoin **official sites** have been hit by front-end exploits (redirect → malware / drainers). Phishing and address poisoning are ambient risk.

**Implication — promote trust engineering without “safe coin” claims:**

| Idea | Tier | Note |
|------|------|------|
| Ship parity (live = disk mint + buy) | **0** | Wrong mint on live = catastrophic trust fail |
| Mint constant single-source | **5** until drift | Promote if drift reappears |
| Keep claims bound to public sources | **6** permanent | Source links carry the evidence |
| Explorer + GeckoTerminal deep-links near CA | **1** done | Same canonical pool without Dexscreener's stale profile destinations |
| CSP / SRI / Webflow script inventory | **5** spare | Only if ship is stable |

### 4. What “survives” vs what we control

Outside research (repeated pattern): most memecoins die fast; survivors share **liquidity depth, distribution, community through drawdowns**, not feature count.

We do **not** control price or liquidity. We control:

1. Whether the site lies (ship lag, mint drift).  
2. Whether culture has a **participation loop** (Studio).  
3. Whether builders can inspect the tools (OSS).

## Research takeaways (short)

Memecoins are culture and speculation, not utility platforms—so Dasha should **not** compete by adding trading features or pump-template sections. It should compete by being **harder to scam-yourself on** (mint desk, CA literacy, live=disk) and **easier to participate in the bit** (Studio). Open source multiplies that only if the **live site matches the repo**, the README has a **demo**, and hygiene doesn’t outrun actual use. Generic landing CRO (TG, roadmap, airdrops) is mostly a **what-not-to-build** checklist for this product.
