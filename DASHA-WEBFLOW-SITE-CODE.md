# Webflow site-level custom code

Some of what ships on getdasha.com is **not in this repo**. Webflow's Site Settings → Custom Code →
Head applies to every page, and nothing in `git` reflects it. This file exists so that code is not
invisible: if you are looking for markup that appears on all five surfaces and cannot find it in any
`dasha-*.html`, it is here.

Read or write it with the Webflow MCP:

```
data_scripts_tool → get_site_freeform_code { site_id }
data_scripts_tool → set_site_freeform_code { site_id, location: 'head', content }
```

**`set_site_freeform_code` replaces the entire block.** Read first, append, write back. The favicon
markup below is easy to destroy with a careless write and hard to notice missing.

## What is in the head block today

1. **Favicon set** — inline SVG data URI (slot-machine cherries) plus PNG fallbacks. Canonical source
   is `dasha-favicon.svg`; regenerate the PNGs from it rather than editing them.
2. **`document.documentElement.lang ||= 'en'`** — a one-liner because Webflow does not always emit it.
3. **Cross-document view transitions** — added 2026-08-12.

## Why the view-transition rule lives here and not in a surface

A cross-document transition needs `@view-transition { navigation: auto }` on **both** the page being
left and the page being entered. Putting it in `dasha-landing.html` alone does nothing.

Site-level is also the only place that covers `/studio` without editing `dasha-studio-embed.html`,
which is generated by `dasha-studio-embed-build.mjs` — a hand edit there is overwritten on the next
build, and both files were mid-rewrite by another agent when this shipped.

The whole effect is the default cross-fade, deliberately. A bespoke transition running between two
pages that are published separately is a thing that can desynchronise; a cross-fade cannot.
`prefers-reduced-motion: reduce` sets `navigation: none`, so asking for less motion turns navigation
transitions off entirely rather than shortening them — verified live: the transition fires under
`no-preference` and does not under `reduce`.

## How it is protected

`dasha-release-contract.json` requires the literal `@view-transition` on the `home` and `studio`
surfaces, so `verifyLive()` fails the publish if the rule ever disappears from Site Settings. That is
the only guard — this block cannot be gated at the source, because the source is not here.
